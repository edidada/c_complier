# 编译器整体规划

> 目标：交付一个可运行、可评分的 C 子集编译器，对标《上机实验》要求（基础 23 分 + 加分项），
> 覆盖「词法分析 → 语法分析 → 类型检查 → 中间代码 → 汇编生成 → 运行验证」完整链路。

## 1. 现状盘点

### 1.1 已有实现（当前代码已具备）

| 模块 | 文件 | 现状 |
|---|---|---|
| 词法分析 | `scanner.l` (67 行) | 关键字/运算符/标识符/整型常量，基础完整 |
| 语法分析 | `parser.y` (768 行) | 程序/声明/表达式/语句/控制流，优先级齐全，悬空 else 已处理 |
| 抽象语法树 | `abstract_syntax_tree/` | 节点类型丰富（表达式、语句、定义、块） |
| 符号表 | `symbol_table/` | Symbol/SymbolTable/FuncSymbol，作用域 + 局部查找 |
| 中间代码 | `intermidiate_code/interCode.*` | 四元式 QuadItem，回填机制（trueList/falseList） |
| 汇编生成 | `asm/AsmGenerate.*` | 寄存器分配（eax/ebx/ecx/edx），算术/跳转/print/scanf |
| 测试程序 | `test_code/test1~6.c` | 基础运算、for、while、指针、一维数组、整除取模 |

### 1.2 已知缺陷（必须先修）

| # | 缺陷 | 现象 | 根因 |
|---|---|---|---|
| D1 | **变量重复定义误报** | test1.c 中 `int a;` 报重复定义，随后进程 **SIGILL 崩溃** (exit 132) | `Body_Generate` 对声明语句 `Def_Stmt → Def_Var → DefList → Def_Single_Var` 存在**递归双重处理**，同一变量被 `addSymbol` 两次，第二次 `findSymbolLocally` 命中即误报 |
| D2 | 声明与语句混排导致崩溃 | 声明语句处理链深嵌套，处理 `Def_Single_Var` 时空指针/非法访问 | 递归路径不唯一、缺少空指针保护 |
| D3 | 错误恢复弱 | 语法错误后无法继续分析（`yyerror` 直接退出） | 无 `%error-verbose`、无错误同步 token |
| D4 | 类型检查缺失/不完整 | 未系统验证类型一致性 | 有待确认与补全 |
| D5 | 代码优化缺失 | 中间代码直接翻译，无优化 | 优化得 1 分，需补 |
| D6 | 运行时库耦合 | 生成代码写入 `asm/test.asm` 依赖 `aso_io.inc` 的 print/scanf | 维持现状即可，但需保证输出稳定 |

## 2. 阶段划分（Roadmap）

> 每个阶段有明确的交付物与验收标准，验收通过后才进入下一阶段。

### 阶段 0：基础设施与缺陷修复（先决条件）
- [x] 0.1 修复 D1 重复定义误报：重构声明语句的符号表处理为**单一路径**
- [x] 0.2 修复 D2 崩溃：全链路空指针保护，删除导致 SIGILL 的路径
- [x] 0.3 构建链路回归：`cmake -B build && cmake --build build && ctest` 全绿
- [x] 0.4 验收：test1~6 全部编译→运行→输出正确

### 阶段 1：词法分析完善
- [x] 1.1 输出格式规范：单词/词素/属性（对照《词法分析器上机要求》样例）
- [x] 1.2 词法错误处理：非法字符、未闭合注释、整数溢出
- [x] 1.3 验收：词法测试用例全部通过（见 04_测试用例.md）

### 阶段 2：语法分析完善
- [x] 2.1 文法覆盖核对：对照实验要求逐项确认（声明/赋值/while/for/if/输入输出/注释）
- [x] 2.2 语法错误恢复：错误同步点（; } 等），一次编译报多个错误
- [x] 2.3 悬空 else、优先级回归
- [x] 2.4 验收：语法测试用例全部通过

### 阶段 3：语义分析（类型检查）

## 3. 优先级与依赖

```
阶段0（必须最先，阻塞一切）
  ↓
阶段1/2（词法/语法，可并行）
  ↓
阶段3（语义）→ 阶段4（中间代码）→ 阶段5（汇编）
  ↓
阶段6（优化/错误）与阶段7（加分项）可并行
  ↓
阶段8（集成/报告）
```

## 4. 验收标准（总）

1. 输入任意满足语法的 C 子集程序，编译器输出可汇编、可链接、可运行的 32 位程序
2. 运行结果与 C 语义一致（用 test1~6 及新增用例回归）
3. 错误输入给出清晰、带定位的错误信息，且一次编译可报多个错误
4. `cmake --build` 全绿，CTest 通过，CI（GitHub Actions）通过
5. 实验报告可完整叙述各模块设计，与代码一致
