# 编译器概要设计

## 1. 总体架构

采用经典三段式编译器结构（前端 / 中端 / 后端），数据单向流动：

```
┌────────────────────────────── 前端 ──────────────────────────────┐
│  C 源程序 (.c)                                                    │
│     │                                                             │
│     ▼                                                             │
│  scanner.l (flex) ──token 流──▶ parser.y (bison)                 │
│     词法分析                      语法分析（LALR(1)）              │
│     (产出 Token)                  (产出抽象语法树 AST)             │
│                                        │                          │
│                                        ▼                          │
│                              abstract_syntax_tree/               │
│                              (AbstractAstNode + 子类)             │
└──────────────────────────────────────┬────────────────────────────┘
                                       ▼
┌────────────────────────────── 中端 ──────────────────────────────┐
│  symbol_table/ ───── 符号表与类型检查（语义分析）                   │
│       │                                                            │
│       ▼                                                            │
│  intermidiate_code/interCode.*                                     │
│  中间代码生成（四元式 QuadItem，回填 true/false 链）                 │
└──────────────────────────────────────┬────────────────────────────┘
                                       ▼
┌────────────────────────────── 后端 ──────────────────────────────┐
│  asm/AsmGenerate.*  ──▶  目标汇编 (32 位 x86, NASM 语法)           │
│       │                                                            │
│       ▼                                                            │
│  asm/test.asm ──nasm -f elf32──▶ test.o ──gcc -m32 -no-pie──▶ test│
│       （打印/输入依赖 aso_io.inc 运行时库）                          │
└────────────────────────────────────────────────────────────────────┘
```

## 2. 模块划分与职责

| 模块 | 主要文件 | 职责 | 对外接口 |
|---|---|---|---|
| 词法分析 | `scanner.l` | 识别 token、词素、属性；词法错误 | `int yylex()` |
| 语法分析 | `parser.y` | 文法分析、构建 AST、语法错误恢复 | `int yyparse()` |
| 抽象语法树 | `abstract_syntax_tree/AstNode.h/.cpp` | 树节点定义、打印 | `AbstractAstNode` |
| 符号表 | `symbol_table/symbol.h` 等 | 符号定义、作用域、重复定义检测 | `SymbolTable` |
| 语义分析 | 新增 `semantic/`（建议） | 类型检查、声明收集 | `SemanticAnalyzer` |
| 中间代码 | `intermidiate_code/interCode.h/.cpp` | 四元式生成、回填 | `InterCode` |
| 汇编生成 | `asm/AsmGenerate.h/.cpp`、`asm/AsmCode.h` | 四元式→x86 汇编、寄存器分配 | `AsmGenerate` |
| 运行时库 | `asm/aso_io.inc`、`asm/asm_io.asm` | print/scanf 等 I/O 支撑 | NASM `%include` |
| 驱动 | 主程序（现有 `scanner_parser_test`） | 命令行入口、调用链编排、输出文件 | `main(argc, argv)` |

## 3. 数据流与关键数据结构

### 3.1 Token
```cpp
// scanner.l 产出（yylval 携带属性）
enum Token { IDENTIFIER, CONST, ADD, SUB, ..., WHILE, FOR, ... };
// 词素: yytext（strdup 后由 yylval.str 携带）
// 属性: 常量数值 / 符号表指针
```

### 3.2 抽象语法树节点
```cpp
class AbstractAstNode {
    std::string content;         // 节点内容（如 "+", "int", 变量名）
    AbstractAstNode* parent;
    AbstractAstNode* first_child;
    AbstractAstNode* next_sibling;
    // 打印、遍历接口
};
// 子类按语义分类：表达式、语句、声明、块、描述符（见详细设计）
```

### 3.3 符号表
```cpp
class Symbol {
    std::string name;
    SymbolType type;             // integer / var(指针/数组基) / func ...
    int sym_offset;              // 栈帧偏移
};
class SymbolTable {              // 作用域，父子链
    Symbol* findSymbol(name);        // 向上查找
    Symbol* findSymbolLocally(name); // 仅当前作用域
    void addSymbol(Symbol*);         // 重复定义在此检测
    int getOffset();  void setOffset(int);
};
class FuncSymbol {               // 函数符号：参数表、返回类型
    std::vector<SymbolType> args;
    SymbolType returnType;
};
```

### 3.4 中间代码（四元式）
```cpp
enum OpType { addtion, substract, ..., assign, logic_and, ...,
              label, JUMP, JUMP_LT/LE/GT/GE/EQ/NE, RETURN_OP, PRINT, SCAN };
union Arg { int target; Symbol* var; };
class QuadItem {
    Arg result; OpType op; Arg arg1, arg2;
    void backpatch(int target);
};
class InterCode {
    std::vector<QuadItem*> quad_list;
    std::stack<std::list<int>> trueList, falseList;  // 回填
    SymbolTable* Body_Generate(AbstractAstNode*, SymbolTable*);
    void Generate(AbstractAstNode*, SymbolTable*);
};
```

### 3.5 汇编代码
```cpp
enum asmRegister { eax, ebx, ecx, edx, ebp, esp, unset };
class AsmCode {                 // 指令序列（字符串拼接）
    void add/sub/mul/div/mov/push/pop(reg, reg|imm);
    void jmp/jne/... 及标签管理;
};
class AsmGenerate {
    void generateArithmetic(QuadItem);   // 四则/取模/幂/赋值
    void generateJump(QuadItem);         // 条件/无条件跳转
    // 目标：print/scan、函数调用、数组/指针寻址
};
```

## 4. 关键技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 语法分析 | LALR(1)（bison），优先文法/结合性声明 | 已实现，改动小 |
| 悬空 else | `%prec LOWER_THAN_ELSE` + 移进优先 | 已实现，保持 |
| 中间代码 | 四元式 + 真值/假值回填 | 已实现，适合条件表达式与短路逻辑 |
| 目标平台 | 32 位 x86（ELF32）+ NASM + gcc -m32 -no-pie | 实验要求汇编目标；链接简单 |
| 运行时 I/O | `print_int` / `scanf` 由 asm_io.asm 库提供 | 已实现，输出稳定 |
| 符号表处理 | **两趟式**：先收集声明建表，再生成代码（修复 D1 的关键） | 避免递归双处理导致重复定义误报 |
| 类型检查 | AST 上独立的语义分析遍（新增 `semantic/` 模块） | 与代码生成解耦，职责清晰 |
| 代码优化 | 中间代码级：常量折叠 + 死代码删除 | 实现简单，满足 1 分要求 |
| 错误处理 | 词法/语法/语义三级错误，带定位信息，尽量继续编译 | 满足错误分析 1 分 |

## 5. 与实验要求的分值映射

```
词法分析 6 分  → scanner.l 完善（阶段1）
语法分析 8 分  → parser.y 完善 + 错误恢复（阶段2）
类型检查 5 分  → semantic/ 新增（阶段3）
代码优化 1 分  → 中间代码级优化（阶段6）
错误分析 1 分  → 三级错误处理（阶段6）
汇编程序 2 分  → AsmGenerate + 运行验证（阶段5）
加分项        → 函数/数组/指针/结构体（阶段7）
```

## 6. 部署与构建

- 构建：CMake（`cmake -B build && cmake --build build`），产物：
  - `build/scanner_parser_test`：编译器主程序（读 .c → 生成 `asm/test.asm`）
  - `build/test`：测试程序可执行文件（nasm + gcc -m32 生成）
- 依赖：flex、bison、nasm、gcc-multilib（32 位 libc）
- CI：`.github/workflows/cmake_ubuntu.yml` 已配置，需保持全绿
